# 新增其他品牌 MLCC 型号解析功能

## Context（背景）

微容页面的型号筛选当前只支持解析微容自家型号（A/T/B/V 开头）和带单位的规格描述（如 `0402,100nF,±10%,50V,X7R`）。用户需要在型号筛选输入框中输入其他品牌（国巨 YAGEO、风华 FH、火炬 Torch、村田 Murata）的 MLCC 贴片电容型号，点"解析"按钮后自动选中各筛选项（尺寸、介质、容量、偏差、电压），以便后续按规格筛选对应的微容产品。

当前 `parseAndFill`（renderer.js:423-575）在微容型号解析失败后仅回退到 `parseDescLoose`，而 `parseDescLoose` 对纯型号字符串（如 `CC0402KRX7R0BB103`、`GRM32EC72A106KE05L`）无能为力。本次新增一个专门的"其他品牌 MLCC 型号解析器"，补齐这个缺口。

## 各品牌命名规则（已通过官方规格书/datasheet 核实）

### 国巨 YAGEO（CC 开头）
格式：`CC` + 尺寸(4) + 偏差(1字母) + `R` + 温度特性(3)+内部电压编码(1) + 版本(2字母) + 容量码(3)
- 温度相关段为 **4 位整体**（如 `X7R0`、`X5R8`、`Y5V9`）：前 3 位为介质代码，第 4 位为国巨内部电压编码（仅用于正则完整性校验，**不解析为 volt 字段**）
- 介质 = 4 位串的前 3 位（如 `X7R0` → `X7R`）
- 案例 `CC0402KRX7R0BB103` → CC + 0402 + K + R + X7R0 + BB + 103 → 尺寸0402, 偏差K(±10%), 介质X7R, 容量103(=10nF)
- **限制**：型号中的第4位内部电压编码不对应标准电压值（如 `0` 不代表 0V，而是内部等级标识），无法可靠推导，volt 字段始终留 null，用户需手动选择电压
- Y5V 介质不在微容筛选项中，temp 设为空

### 风华 FH（4位数字开头）
格式：尺寸(4) + 介质(B/CG/X) + 容量码(3) + 偏差(1字母) + 电压码(3) + 包装(2+)
- 介质代码：B=X7R, CG=C0G（官方确认）, X=X5R
- 电压码用**标准 EIA 码**（官方确认）：500=50V, 160=16V, 201=200V, 202=2000V
- 案例 `0603B101K500NT` → 0603, X7R, 100pF, ±10%, 50V

### 火炬 Torch（FCC 或 HGC 开头）
- FCC 格式：`FCC` + 尺寸(4) + 介质(1字母) + 容量码(3) + 偏差(1字母) + 电压码(3) + 包装
  - 案例 `FCC1206X226K250HT` → 1206, X5R, 22µF, ±10%, 25V
- HGC 格式：`HGC` + 尺寸(4) + 介质码(2) + 容量码(3) + 偏差(1字母) + 电压码(3) + 包装
  - 案例 `HGC0805R5476M100NSLJ` → 0805, R5(=X5R), 47µF, ±20%, 10V
- **火炬介质码统一映射表**（FCC 单字母 + HGC 2位码共用）：
  - FCC 单字母：`X`→X5R, `B`→X7R, `C`→C0G
  - HGC 2位码：`R5`→X5R, `R7`→X7R, `N4`→C0G
  - 未命中的码 → temp 置空（不再有"R5 含义不明留空"的逻辑）

### 村田 Murata（GRM 开头，固定 18 位）
格式：`GRM`(3) + 尺寸(2) + 厚度(1) + 介质(2) + 电压(2) + 容量码(3) + 偏差(1字母) + 规格(3) + 包装(1)
- 尺寸码：02=0402, 03=0603, 05=0805, 06=1206, 08=1210, 15=0201, 18=0603, 21=0805, 31=1206, 32=1210, 55=1812
- 介质码：5C=C0G, R6=X5R, R7=X7R, C7=X7S（datasheet 确认）
- 电压码：0J=6.3V, 1A=10V, 1C=16V, 1E=25V, 1H=50V, 2A=100V, 2D=200V, 2E=250V 等
- 案例 `GRM32EC72A106KE05L` → 1210, X7S, 10µF, ±10%, 100V

## 实现步骤

### 步骤 1：新增 `eiaCodeToVolt(code)` 工具函数
**文件**：`matcher-core.js`，插入在第 86 行后（`eiaCodeToPf` 之后）
逻辑与 `eiaCodeToPf` 完全一致：前两位有效数字 + 第三位 10 的幂；含 R 表示小数点。
用于解析风华/火炬的 3 位 EIA 电压码。
**支持的电压码**（复用容量码算法，无需额外映射表）：
- 数字型三位码：前两位有效数字 × 10^(第三位)，单位 V
  - `500`→50V, `160`→16V, `250`→25V, `101`→100V, `201`→200V, `202`→2000V, `102`→1000V
- 含 R 格式：R 替换为小数点后转浮点数
  - `6R3`→6.3V, `2R5`→2.5V, `4R0`→4.0V

### 步骤 2：新增 `parseOtherBrandMlcc(name)` 主函数及 4 个子函数
**文件**：`matcher-core.js`，插入在第 253 行后（`parseProductName` 之后）

主函数按前缀分发：
- `CC` 开头 → `parseYageo(s)`
- `FCC`/`HGC` 开头 → `parseTorch(s)`
- `GRM` 开头 → `parseMurata(s)`
- 4位数字开头 + (B|CG|X) → `parseFenghua(s)`

每个子函数用 `^...$` 锚定正则严格匹配，复用模块内已有的 `eiaCodeToPf`、`devLetterToNorm`、`tempCode`，以及新增的 `eiaCodeToVolt`。村田的尺寸/介质/电压码用查找表映射。

**各子函数关键正则与逻辑**：

- `parseYageo(s)`：正则 `^CC(\d{4})([A-Z])R([A-Z0-9]{4})([A-Z]{2})([\dR]{3})[A-Z]*$`
  - 温度相关段为 4 位整体（如 `X7R0`），介质取前 3 位：`temp = tempCode(m[3].substring(0, 3))`
  - Y5V → temp 设为空（微容筛选项无 Y5V）
  - `volt: null`（国巨内部电压编码不解析）

- `parseFenghua(s)`：正则 `^(\d{4})(B|CG|X)([\dR]{3})([A-Z])(\d{3})[A-Z]{1,3}$`
  - 介质映射：B→X7R, CG→C0G, X→X5R
  - 电压用 `eiaCodeToVolt(voltCode)`

- `parseTorch(s)`：
  - FCC 正则 `^FCC(\d{4})([A-Z])([\dR]{3})([A-Z])(\d{3})[A-Z]*$`，介质单字母映射
  - HGC 正则 `^HGC(\d{4})([A-Z0-9]{2})([\dR]{3})([A-Z])(\d{3})[A-Z]*$`，介质2位码映射
  - 统一介质映射表：FCC `{X:X5R, B:X7R, C:C0G}` + HGC `{R5:X5R, R7:X7R, N4:C0G}`
  - HGC 的 R5 不再留空，映射为 X5R

- `parseMurata(s)`：正则 `^GRM(\d{2})([A-Z0-9])([A-Z0-9]{2})([A-Z0-9]{2})([\dR]{3})([A-Z])([A-Z0-9]{3})([A-Z])$`
  - 尺寸映射表新增 `55→1812`
  - 介质映射：5C→C0G, R6→X5R, R7→X7R, C7→X7S
  - 电压映射：0J→6.3V, 1A→10V, 1C→16V, 1E→25V, 1H→50V, 2A→100V 等

返回格式与 `parseProductName` 对齐：`{ series: null, cap, dev, size, temp, volt, raw }`（series 始终 null，其他品牌无微容 A/T/B/V 系列）。

### 步骤 3：导出新函数
**文件**：`matcher-core.js` 第 913 行
在 `module.exports` 中追加 `parseOtherBrandMlcc`。

### 步骤 4：前端接入
**文件**：`renderer.js` 第 442-445 行
在 `parseProductName` 失败后、`parseDescLoose` 之前，插入对 `parseOtherBrandMlcc` 的调用：
```javascript
// 如果微容型号解析失败，尝试其他品牌MLCC型号解析（国巨/风华/火炬/村田）
if (!spec) {
  spec = matcherCore.parseOtherBrandMlcc(text);
}
```
现有 `parseAndFill` 的填充逻辑（series/size/temp/cap/dev/volt 替换式赋值）完全兼容新函数的返回格式，无需改动：
- `spec.series` 为 null → 跳过系列填充
- `spec.size` 是 4 位 inch 码 → 已有 sizeMap 映射
- `spec.temp` 可能为空 → `if (spec.temp)` 跳过
- `spec.volt` 为 null → `if (spec.volt !== null)` 跳过
- `spec.dev` 如 `±80%-20%` 不在 devMap → 优雅跳过

## 边界情况处理

| 情况 | 处理 |
|------|------|
| 国巨型号内部电压编码不对应标准电压值 | volt 始终设为 null，用户手动选择电压 |
| Y5V 介质不在微容筛选项 | temp 设为空字符串 |
| 国巨 Z 偏差(±80%-20%)不在筛选项 | devMap 查找失败，优雅跳过 |
| 火炬 HGC 介质码 R5/R7/N4 | 映射为 X5R/X7R/C0G，不再留空 |
| 火炬未知介质码 | temp 置空，其他字段正常 |
| 村田未知尺寸码 | 解析失败返回 null |
| 村田未知介质/电压码 | 对应字段留空/null，其他字段正常 |
| 小写输入 | 主函数开头 toUpperCase() |
| 容量码无法解析 | eiaCodeToPf 返回 null，子函数返回 null |
| 非品牌型号/规格描述 | 所有子函数不匹配 → 返回 null → 走 parseDescLoose |

## 用户工作流

1. 在"产品型号"输入框输入其他品牌型号（如 `CC0402KRX7R0BB103`）
2. 点"解析"按钮 → parseAndFill 自动填充筛选项（尺寸、介质、容量、偏差、电压）
3. 点底部"查询"按钮（runFilter）→ 按规格筛选微容产品

注意：用户不应点"解析"旁的"查询"按钮（parseAndQuery，productNameOnly=true），那是子串匹配微容型号用的。
